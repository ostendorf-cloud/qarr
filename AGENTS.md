# qarr

The global baseline already applies here and is not repeated below.

## Layout

- `cmd/qarr` wires the app: configuration, the two HTTP listeners, shutdown. `embed.go` embeds
  `dist/` (the built SPA, written by `task web:build`), sitting under `cmd/` rather than
  `internal/` because `go:embed` resolves relative to the file holding the directive.
- `internal/config` loads and validates the app's own environment once, aggregated into one
  error.
- `internal/webapp` builds the two `http.Handler`s govue's `httpserver.RunAdmin` serves: the
  public one, the embedded SPA; the admin one, health, readiness and metrics, reached only from
  inside the cluster.
- `internal/depsync` checks that `go.mod` and `web/package.json` pin the same govue tag, and
  that `web/pnpm-lock.yaml`'s own resolution of it still carries govue's Vue package
  subdirectory. A generic pattern, not qarr's own domain logic.
- `web/` is the Vue single page application, consuming govue's Vue package as a pnpm git
  dependency. One start page and the imprint and privacy pages, prerendered in German and
  English, see "Legal pages" below; see "What this app will become" for what grows here.
- `charts/qarr/` is the Helm chart that installs this service on a Kubernetes cluster.

## A build needs the frontend first

`cmd/qarr` cannot compile against an empty `dist/` directory, because `go:embed` fails when its
pattern matches no file at all. `dist/` is gitignored, generated by `task web:build`.

`task build` and `task test:go` both declare that dependency, so running either one through Task
always populates the frontend first. A bare `go build ./cmd/qarr` or `go test ./cmd/qarr/...`
outside Task fails on a fresh checkout for that reason; run `task build` or `task test:go`
instead, or `task web:build` once by hand before reaching for the Go toolchain directly.

## govue's two halves move together

govue releases a Go module and a Vue package under one tag. `go.mod`'s
`require github.com/ostendorf-cloud/govue` and `web/package.json`'s `@ostendorf-cloud/govue`
pnpm git dependency must always name the same tag: a mismatch means this repository takes half
of a govue release and not the other half, silently. `task check:govue-version`
(`internal/depsync`) enforces this, the same way ostendorf.tech's own copy of this check does.

## What this app will become

qarr encodes and draws a QR code entirely in the browser: a WiFi password, a vCard or any other
payload never leaves the tab, which is the privacy claim the product is built on. Colours and an
optional logo are the user's own. The whole configuration lives in the fragment of the page URL,
never sent to a server, so a style is shareable and reproducible with no account and no storage.
A preset logo comes from a bucket this app reads with a read-only key and serves under its own
origin, which is what keeps the canvas that draws it untainted. An HTTP API is a second surface
for scripts and batch runs, entirely separate from the page, and needs a key: the page itself
calls no API, so the API can require one from every caller without exception.

## Encoding and decoding a QR code

`web/src/qr` encodes a free text payload, draws it on a plain RGBA buffer with the user's own
colours, module shape and an optional logo, and decodes that same buffer again before the page
shows it. All of it runs in the tab; nothing in `web/src/qr` or the components that call it makes
a network request. See [0001](docs/adr/0001-the-browser-renders-the-api-is-a-second-surface.md).

- Encoder: [`qrcode-generator`](https://www.npmjs.com/package/qrcode-generator), pinned to
  `2.0.4`. It implements the standard's own mask selection rather than picking a mask of its
  own, and it exposes the module matrix directly, which this app needs to draw its own colours,
  shape and logo rather than being handed a finished picture.
- Decoder: [`jsqr`](https://www.npmjs.com/package/jsqr), pinned to `1.4.0`. A pure JavaScript
  decoder with no WebAssembly build to load and no worker to set up, which keeps the decode
  check to the draw-time cost alone rather than a whole scanning UI.
- Measured bundle cost, each bundled on its own with Vite at the same settings `task web:build`
  uses, minified and gzipped: `qrcode-generator` is 20.62 kB (7.29 kB gzipped), `jsqr` is
  130.48 kB (47.74 kB gzipped), the two together are 151.14 kB (53.75 kB gzipped). The decoder
  is the larger cost by far; it is kept anyway because the decode check after drawing is what
  this issue's logo-and-error-correction-level choice is verified against rather than assumed.
- A logo covers part of the code, so the error correction level and the covered area are chosen
  together: `web/src/qr/style.ts` raises the level to fit the logo's share of the edge where it
  can, `web/src/qr/render.ts` then draws and decodes the result, and raises the level or shrinks
  the logo further whenever that drawn code does not read back, until it does or nothing is left
  to try. A style that cannot be repaired is reported rather than shown. The threshold that
  gates all of this, `web/src/qr/style.ts`'s `MIN_CONTRAST`, is WCAG 2.2's non-text 3:1 floor,
  borrowed as a conservative stand-in rather than derived from how a decoder's own binarisation
  behaves: nothing sourced ties a WCAG-style luminance ratio to that, and ISO/IEC 18004's own
  contrast requirement is a different metric (a reflectance difference) with a different number.
- `web/src/qr/export.ts` turns the already-verified drawing into a PNG and an SVG. The PNG is
  the same raster the decode check ran on, re-encoded as a file. The SVG is not: it is a second
  drawing of the module grid, built from the matrix and the style rather than from that raster,
  with only the embedded logo picture reused byte for byte. `export.test.ts` guards the SVG
  instead, by walking its own shapes and comparing them cell by cell against the matrix the
  decode check ran on. Rasterising the generated SVG and decoding it with jsQR would be the
  stronger check, closing this gap entirely, but this project has no tool to rasterise an SVG in
  its test environment, so that check is not attempted.

## The configuration lives in the page URL

`web/src/url/fragment.ts` encodes the text and the style (shape, foreground, background) into
the fragment of the page's own address, and decodes it back. See
[0002](docs/adr/0002-the-configuration-lives-in-the-page-url.md).

- A logo is left out of the link entirely, the same way the previous attempt at this app left it
  out: its pixels would make the link far too long to paste, and a shared style does not have to
  carry a picture. Reopening a link never restores a logo.
- The fragment carries a version under its own `v` field. Decoding is forgiving per field rather
  than all-or-nothing: a field a fragment does not carry falls back to its default instead of the
  whole link being refused, which is what lets a link made today keep opening once the format
  grows a field later. A change that cannot be read this way gets a new `CURRENT_VERSION` and its
  own branch in `decodeFragment`; an already-released version's branch is never edited once a
  later one exists. `fragment.test.ts` proves this against a hand written fixture of an older
  shape, not only a round trip of today's encoder.
- `web/src/composables/useUrlFragment.ts` binds this to the page: it restores the configuration
  once on creation, then keeps the address bar's fragment current as either the text or the style
  changes, debounced and written with `history.replaceState`. Never `pushState`, and never a plain
  assignment to `location.hash`: both of those add a browsing history entry, which would turn
  every keystroke into something a "back" press has to undo one at a time. `replaceState` adds no
  entry no matter how often it runs; the debounce exists only so a fast typist does not ask the
  browser to rewrite the address bar on every keystroke, not to protect history.
- A fragment this page cannot parse, or one written by a version it does not know, decodes to
  `null` rather than throwing, and the page falls back to its ordinary empty defaults: a corrupt or
  future link leaves a usable page, not an error screen.
- `COMFORTABLE_FRAGMENT_LENGTH` (`web/src/url/fragment.ts`) is 600 characters of the encoded
  fragment itself, past which the page warns. Chosen rather than measured: an ordinary WiFi
  password or a short link encodes to a little over half of that, so 600 leaves room for the
  common case while still catching a configuration that has grown uncomfortable, well before a
  browser's own practical limit (older browsers and some proxies choke well under 2000 characters
  for a whole URL). The warning shows on the page itself as soon as the threshold is crossed, so
  it is seen before the address is copied anywhere, not after.

## Guided input

`web/src/qr/guided` turns a kind and the strings of its form into the text a scanner reads. One
file per format, each naming its standard in the header comment; `index.ts` holds the kinds, the
field list of each form (`SPECS`) and `serialize`. Everything is pure and runs in the tab.

- WiFi (ZXing "Barcode Contents", `WIFI:`), vCard 3.0 (RFC 2426), iCalendar VEVENT (RFC 5545),
  `tel:` (RFC 3966) and the EPC QR code for SEPA (EPC069-12, version 002, UTF-8, SCT).
- An encoder returns `{ ok, payload }` or an error code per field. It writes no prose: the code
  maps to a message in `web/src/i18n/messages.ts`, German and English, merged into govue's
  language layer under `qarr`. Only the guided input is translated so far, the rest of the start
  page stays English (see "Legal pages").
- The fragment keeps `v: 1` and gains optional `kind` and `fields`. A link without them is free
  text. Only the active kind's non-empty fields travel, and only keys the form knows are restored.
- A switch of type keeps what can be kept: a field with the same `carry` name moves over, every
  form keeps its own entries for the way back, and `useQrCode().notice` names what was left
  behind. The page says it in a status line.
- `web/src/qr/matrix.ts` sets the encoder's byte conversion to UTF-8. The library default drops
  the high byte of every UTF-16 unit, which corrupts anything beyond ASCII and breaks the EPC
  code's UTF-8 claim. A test decodes a code per kind with non-ASCII text.
- An error shows at its field once the field was left, never before.
- The appointment's DTSTAMP is the time the string is built, so the code of an appointment
  differs between two openings of the same link. Its UID is a hash of the event's fields.
- The entries are plain text in the link. The forms say so at the WiFi password and the IBAN,
  and the privacy page says a copied link and the history keep them. An open WiFi network
  carries no password in the link. The BIC is required outside the EEA (EPC069-12 v3.1).
- A `(0)` right after a country code in a phone number is dropped, any other `(0)` is refused.
- Not checked: that an IBAN has the length its country fixes (only the MOD 97 check), that a
  WiFi network name made of hex digits is read as text by every phone, and any BIC against a
  directory.

## Page view counting

The server reports page views to Umami through govue's `analytics` package. Nothing is built
here that govue provides. Off unless `UMAMI_URL` and `UMAMI_WEBSITE_ID` are both set.

- `internal/webapp.Handler` puts `views.Middleware` innermost, directly around the mux, because
  it reads `r.Pattern`. Every page is an exact pattern (`/de/`, `/en/privacy`), so the reported
  URL is that fixed pattern: what a user encodes can be in a path or a query only by hand, and
  is never reported. Moving the middleware outside `RequestID` loses the pattern and counts
  nothing; `analytics_test.go` fails then. The redirects (`/`, `/imprint`, `/impressum`) answer
  302 and are never counted.
- A new public route is registered on the mux with a pattern. A page with a variable part in its
  path reports the pattern, not the value. An API route needs `Options.Skip`.
- `SITE_URL` (default `https://qarr.de`) is the public origin. Umami gets its bare host. The web
  build bakes `https://qarr.de` into the canonical and hreflang links and the sitemap
  (`entry-prerender.ts`); the server replaces it by `SITE_URL` when it loads the pages.
- `TRUSTED_PROXIES` must name the ingress, or every view comes from the proxy and none counts.
- A change to what is reported needs an update of `web/src/pages/PrivacyPage.vue` (both
  languages) and the README section "Privacy and page view counting".

## Legal pages

Nothing govue provides is built here: `language.HandleLegal`, `GovueLegalPage` and
`govue-check-legal` do the routes, the page shell and the check.

- `web/src/site.ts` is the route table and the page of each path. The browser entry
  (`main.ts`) and the prerender entry (`entry-prerender.ts`) both read it. A page added there
  is prerendered and listed in `sitemap.xml`, and the server serves exactly the pages that file
  lists (`internal/webapp/site.go`), so Go holds no second route table.
- `task web:build` runs the client build, the SSR build, `govue-prerender` and
  `govue-check-legal`. A page without the imprint and privacy links of its language fails it.
- qarr has no terms. `LegalConfig.Terms` stays off and `terms` stays out of `pages`. Add both
  together if that ever changes.
- The legal texts are the site's own and state only what the code and this repository back. A
  fact that no document states (hosting provider, retention, legal basis) is not written down.
- The start page text is English only for now, marked `lang="en"`. Header and footer follow the
  language of the address.

## Scope of this milestone

Implemented: the entry point and its two listeners, the health/readiness/metrics admin surface,
the SPA shell and its theme, the Helm chart, the CI set that checks all of it, encoding, drawing,
the logo and error correction repair, the decode check, the PNG/SVG download, and the
configuration living in the page URL fragment, and guided input for WiFi, vCard, an appointment,
a telephone number and a SEPA transfer.

Not implemented yet, later milestones:

- The bucket client for preset logos, and every API route.
- Saved templates, kept in the browser with no account and no server-side storage.
- Batch generation and a print sheet: CSV in, many codes out, as an archive or a cut-marked PDF
  sheet.

## Deviations

- Every CI job runs on `ubuntu-latest`, not a Blacksmith runner: this repository is public, so
  its CI minutes are not billed the way a private repository's are. No
  `.github/actionlint.yaml` self-hosted-runner override file either, for the same reason.
- `.github/workflows/codeql.yaml` and the `license` job inside `checks.yaml` exist because this
  repository is public: code scanning needs no GitHub Advanced Security entitlement here, and a
  per-file license header is enforced the way govue's own is.
- `charts/qarr/values.schema.json`'s top-level `required` array omits `existingSecret`: this
  milestone has no secret-shaped setting at all (no API key, no bucket credential yet), so there
  is nothing for an `existingSecret` value to name. One is added once a later milestone
  introduces its first secret.
- No `NetworkPolicy` template and no single-replica guard in the Helm chart: qarr has no
  workload to restrict egress to yet, and keeps no in-process session state, unlike
  ostendorf.tech's own chart.
